## 1. 背景与目标

API 已公网暴露（https://api.zeroicey.me）且 Web 前端已上线（https://serenique-web.pages.dev），但目前**没有任何认证**——任何人拿到域名即可读写日记。本项目为**个人单用户**、开源可自部署，部署者即唯一用户：**不需要授权 / 多用户 / 角色，只需要认证**（确认请求来自部署者本人）。

约束：

- 单用户 = 部署者本人；无多账号语义。
- 多端：Web（跨域 Cookie）、CLI（Bearer）、MCP（内部直连 + 自有传输）、移动端 Flutter（规划，Bearer）。
- 凭证强度优先：用户明确不信任「人类可记的密码」；SSO 对单用户过度复杂（评估后放弃，留后门）。

---

## 2. 认证模型（已确认方向）

- **单一高熵共享密钥** `AUTH_TOKEN`（≥32 字符，建议 48+）作为唯一凭证，所有端共用。
- 不建账号 / 用户表 / 会话表：**零新表、零迁移**。
- 浏览器：`POST /api/auth/login` 用密钥换 **HttpOnly 签名 Cookie**（无状态，HMAC 签名密钥 = `AUTH_TOKEN`）。
- **换密钥 = 全端失效**（Cookie 签名与新 token 同时失效），满足「收回访问」需求，无需会话表。
- CLI / 移动端：直接用密钥作 Bearer Token，不走 Cookie。

---

## 3. 业务规则

- **生产 fail closed**：`NODE_ENV=production` 且 `AUTH_TOKEN` 缺失 → 启动即拒绝；dev 未设置则跳过认证。
- **常量时间比对**：密钥 / 签名比对用 `timingSafeEqual`（复用 blob 模块既有模式）。
- **Cookie**：`serenique_session`，HttpOnly + Secure + SameSite=None（跨站），默认 30 天（`SESSION_TTL` 可配），格式 `exp.signature`。
- **放行列表**：`/health`、`/`、`/api/auth/login`、签名 blob 文件链接（`/api/blobs/:id/file`，由既有 `expires+signature` 校验把关）。
- **防爆破**：login 失败 sleep ~500ms；同 IP 短窗 ≥5 次失败 → 429 封禁数分钟（内存 Map，单进程即可）。
- 用户可见文案中文。

## 4. API 路由

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth/login` | body `{ token }` → 签发 HttpOnly 会话 Cookie |
| POST | `/api/auth/logout` | 清 Cookie |
| GET | `/api/auth/me` | `{ authenticated: true }`，Web 探登录态 |

认证失败：401 `{ success:false, code:"UNAUTHORIZED", message:"未认证或登录已过期" }`；`shared/errors.ts` 新增 `UNAUTHORIZED`、`RATE_LIMITED` 码。

---

## 5. 模块结构与接线点

- 新目录 `src/modules/auth/`：`auth.types.ts` / `auth.domain.ts`（Cookie 签名 / 验签、常量时间比对，纯函数）/ `auth.service.ts` / `auth.handler.ts` / `auth.router.ts` / `auth.middleware.ts` / `index.ts`（对齐分层骨架）。
- `src/app.ts`：挂 auth 中间件（CORS/logger 之后、模块路由之前）+ `app.route("/api", authRouter)`。
- `src/db/schema.ts`：**无改动**（零表）。
- `src/exports.ts`：视 MCP 需要导出 auth service 类型（MCP 进程内直连，通常不需要 auth）。
- CORS：带凭证跨域不允许 `*`，生产设 `CORS_ORIGIN=https://serenique-web.pages.dev`。

---

## 6. 各端接入

| 端 | 做法 |
|----|------|
| Web | `/login` 页 + `credentials:"include"`；加载时 `GET /api/auth/me` 判登录态；不存 localStorage |
| CLI | `auth login`（打码写入 config）/ `auth logout` / `auth me`；请求自动带 `Authorization: Bearer` |
| 移动端（规划） | 登录页 → 密钥存 Keychain/Keystore → Bearer |
| MCP | 内部直连 DB 不受影响；其 streamable-http（3001）加同密钥 Bearer 校验 |

## 8. 部署

- 根 `.env` 加 `AUTH_TOKEN` + `CORS_ORIGIN=https://serenique-web.pages.dev`。
- **上线前先配密钥**：生产缺 `AUTH_TOKEN` 会启动失败（故意 fail closed）。
- 发布走「推 main → 打 tag」。

## 9. 已定决策

| # | 决策点 | 结论 |
|---|--------|------|
| ① | 方案 | **共享密钥**（A），非账号密码、非 SSO |
| ② | 凭证形态 | 单一高熵 `AUTH_TOKEN`，所有端共用 |
| ③ | Web 登录 | 登录表单 + **HttpOnly 签名 Cookie**（无状态） |
| ④ | 会话表 | **不建**（无状态 Cookie + 换密钥全端失效） |
| ⑤ | users 表 | **不建**（单用户，YAGNI） |
| ⑥ | SSO/OIDC | 现在**不做**；认证层按可插拔策略设计，留 JWT 校验后门 |
| ⑦ | 防爆破 | login 失败 sleep + 同 IP 短窗封禁（内存） |
| ⑧ | 生产缺密钥 | **fail closed**（启动即拒） |
| ⑨ | MCP 传输 | streamable-http 加同密钥 Bearer 校验 |
