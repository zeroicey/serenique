## 1. 背景与目标

AI 对话（宁序）目前只做「会话」本身（模型运行时 + 工具 + 会话持久化），**没有任何记忆注入**：模型不知道当前时间（除会话创建那一刻）、不知道用户的任务/日程/闪记/习惯。用户希望给 AI 注入两类记忆（实施时细分为四层，见 §4）：

1. **长期记忆**：用户背景、偏好、人格设定等静态信息。实施拆分：主管「人格/行为」的由开发者维护（在系统提示词 L1）；主管「用户自画像/偏好」的由**用户自己编辑**（独立成用户画像层 L2，本设计核心新增）。
2. **瞬时记忆**（每次调用前由系统自动注入的动态区）：当前时间、近期任务/日程/闪记/习惯等内部数据快照，随数据变化更新。

目标：

- **系统提示词人格化**：从「工具模板风」改为「温柔俏皮的女生形象」（宁序）。
- **用户画像独立成层**：用户高频编辑的自我介绍/偏好（ai_memory）从系统提示词中拆出，语义与维护权边界清晰。
- **动态上下文注入**：时间 + 内部数据在每次对话轮次（turn）前自动刷新注入，无需模型自己调工具去查。
- **上下文不重复**：动态内容**替换式**更新，不随对话历史逐条累积（防膨胀、防重复）。
- 形成可落地的四层上下文结构：系统提示词（顶层）→ 用户画像（第二层）→ 动态上下文快照（第三层）→ 对话历史（底层）。

**AI 绘画**：用户确认系口误，实际指「AI 会话」——仓库内不存在、也不需要绘画功能，本设计不涉及。

## 2. 术语对照（用户口语 → 专业名词）

| 用户说法 | 专业名词 | 说明 |
| --- | --- | --- |
| 长期记忆（人格/行为类） | **静态系统提示词 / Static system prompt** | L1：人设、准则、工具用法，开发者维护，定稿后不变 |
| 长期记忆（自画像类） | **用户画像 / User profile** | L2：用户自我介绍/偏好/背景（ai_memory），用户自己编辑 |
| 瞬时记忆 | **动态上下文快照 / Ephemeral context snapshot** | L3：每次轮次前系统自动组装并注入的动态区 |
| 每轮更新一次 | **Per-turn refresh** | 每个用户消息 = 一个轮次（agent run），轮次开始前刷新一次快照 |
| 上下文不重复 | **替换式注入 + 数据指纹去重** | 动态块不追加进历史（替换式），数据未变时跳过重复查询/组装 |
| 系统提示词 | **System Prompt** | 最顶层，指导模型行为与人格 |
| 用户提示词 | **User profile prompt** | 第二层，用户自画像，随用户编辑变化 |
| 动态注入的提示词 | **Dynamic context** | 第三层，随轮次更新的环境/数据快照 |
| 具体聊天内容 | **对话历史（Message history）** | 最底层，模型看到的已发生对话 |

## 3. 现状调研结论（Pi SDK 能力边界）

基于本仓库安装的 `@earendil-works/pi-coding-agent` 0.84.1（bun.lock 锁定；dist 源码实读，2026-08-19）：

### 3.1 SDK 不会自动注入时间/日期/用户数据

- SDK 默认系统提示词是「编程助手」风格，**不含当前日期**。仓库现有代码自己用 `buildSystemPrompt(new Date())` 注入日期（`ai.system-prompt.ts`）。
- **缺陷：日期只在会话创建时注入一次**。`DefaultResourceLoader.systemPromptOverride` 在 loader 创建/reload 时求值一次并缓存为 `_baseSystemPrompt`；会话恢复后跨天（如昨天开的会话今天继续聊），日期仍是昨天的。内部数据（任务/日程/闪记/习惯）则完全没有注入——模型需要自己调 `list_*` 工具才能知道，且不说「最近 3 个任务」这种概览，工具查询也要逐一调、多轮往返。

### 3.2 SDK 提供官方「每轮注入」钩子：`before_agent_start` 扩展事件

- 触发时机：**每次用户提交 prompt 后、agent 循环（含思考/工具调用/多 turn LLM 调用）开始前**，恰好一轮一次，即为用户说的「每轮更新一次」。
- 处理器可返回两类结果（`BeforeAgentStartEventResult`，链式叠加）：
  - `systemPrompt`：**替换本轮的系统提示词**——这是动态上下文的落点：每轮组装「静态人格 + 最新快照」整块覆盖，**不进消息历史，天然不重复**。
  - `message`：注入一条 `custom` 消息（转 LLM 时以 user 角色出现）——**会写入会话 jsonl 历史**，每轮追加会累积膨胀，不推荐作为快照载体。
- 注册方式：`DefaultResourceLoaderOptions.extensionFactories: InlineExtension[]` 支持**进程内注册内联扩展**，无需扫描磁盘扩展目录 → 现有 `noExtensions: true` 的安全隔离（不加载 ~/.pi 全局扩展）可以继续保留。
- SDK 无公开的 `setSystemPrompt` API（`systemPrompt` 只读 getter）；`prompt()/steer()/followUp()` 只发用户消息。**因此「每轮替换系统提示词」唯一正路就是 before_agent_start 扩展。**

### 3.3 内部数据源查询能力（复用现有 service，无需新代码路径）

| 数据 | service 调用 | 字段 |
| --- | --- | --- |
| 任务组 | `taskService.listTaskGroups({page,pageSize})` | title |
| 任务 | `taskService.listTasks({page,pageSize,status,dueDateFrom,dueDateTo})` | title/status/dueDate/groupId |
| 日程 | `eventService.list(...)` | title/startAt/endAt/isAllDay/location |
| 闪念 | `momentService.list({page,pageSize})` | text | (text 非 content)
| 习惯 | `habitService.listHabits()` + `habitService.overview(...)` | name/kind/countable + 近期打卡 | (名字/频率概览)

均已有现成实现，快照查询只用轻量字段 + 截断。

## 4. 目标架构：四层上下文

```
┌────────────────────────────────────────────────────┐
│ L1 系统提示词（System Prompt，静态）                 │  ← 人格（温柔俏皮的女生）+ 行为准则 + 工具用法
│     由 buildSystemPrompt() 组装，开发者维护，基本不变  │
├────────────────────────────────────────────────────┤
│ L2 用户画像（User Profile，低频变更）                │  ← 用户自我介绍 + 偏好 + 背景（ai_memory）
│     用户自己编辑（Web 设置页/GET·PUT API），仅编辑时变 │
├────────────────────────────────────────────────────┤
│ L3 动态上下文快照（Dynamic Context，每轮刷新）        │  ← 当前时间 + 任务/日程/闪记/习惯快照
│     由 before_agent_start 钩子组装，整块替换           │
├────────────────────────────────────────────────────┤
│ L4 对话历史（Message History，SDK 管理）             │  ← 用户消息/助手回复/工具调用
└────────────────────────────────────────────────────┘
```

- L1/L2/L3 拼接后作为本轮 systemPrompt 发送给模型（顺序即权重顺序，越靠上越优先）；L4 追加。
- **关键认知（为什么 L3 每轮都要带而不是「有变化才带」）**：LLM 是无状态的，每次调用必须把上下文完整送过去；「不重复」指**不累积不膨胀**（历史里永远只有一份动态块），而不是「省掉重复发送」——快照 token 本身每轮固定支出（用户已确认这部分 token 量小可接受，§6 有预算控制）。
- **去重落在两层**：
  1. 结构上去重：L3 走 systemPrompt 替换，不进历史 → 无论聊多少轮，历史里动态块只有一份（对比：custom 消息注入每轮多一条）。
  2. 数据上去重（省查询）：快照按**数据指纹**缓存，指纹未变（数据无变化）时跳过 DB 重新查询与组装，直接复用上次文本；**时间字段为唯一例外，每轮强制刷新**（跨小时/跨天必须准确）。
- **注入组装**：before_agent_start 钩子返回 `systemPrompt = L1 + L2 + L3`（L1 会话创建时求值一次缓存为常量；L2 读 ai_memory 并按 updatedAt 缓存；L3 每轮重拼）。

## 5. 用户画像（用户提示词）层设计

- **形态**：一段用户可编辑的文本（Markdown/纯文本，建议 ≤2KB），即「用户写给 AI 的自我介绍」：身份、偏好、背景、在意的事。
- **存储**：新增 `ai_memory` 表（单行：id 固定 1、content、updatedAt）+ 最小 API（GET / PUT）。Web 设置页放一个编辑框（本轮后端优先，前端可后置）。
- **注入位置**：独立成 L2，紧邻系统提示词（越靠上权重越高）；只随用户编辑变化，按 `updatedAt` 缓存（编辑后重新读取，不参与每轮刷新）。
- **维护边界**：L1 系统提示词由开发者/专家维护（定稿后基本不动）；L2 用户画像是**用户自己高频编辑的唯一入口**——产品侧「编辑提示词」的界面只对应这块。

## 6. 动态上下文快照（瞬时记忆层）设计

每次在 before_agent_start 中组装 L3（不含用户画像，画像在 L2）：

```
[当前时间]
现在是 2026-08-19（周三）22:41，时区 GMT+8。

[任务概览]
未完成任务（最近 8 条）：『写周报』(今天到期，进行中) | 『整理照片』(无期限) …
任务组：工作 / 生活 / 学习

[近期日程]
今天 15:00-16:00 产品评审；明天 10:00 牙医

[最新闪念]
1. 『想到一个 App 点子…』(今天)

[最近习惯]
喝水（计数型，今天 5/8 次）；跑步（做没做型，近 7 天 3/7 天）
```

- **数据源与配额**（token 预算目标：快照整体 ≤ 1.5~2KB，即 ~500-700 token）：
  - 时间：每轮强制刷新（星期 + 时区 + 具体时分）。
  - 任务：未完成任务取最近 8 条（title + status + dueDate）；任务组取全部（一般很少）。
  - 日程：今天 + 未来 3 天，取 ≤6 条（title + 时间）。
  - 闪念：最新 3 条（text 截断 60 字）。
  - 习惯：全部习惯名 + 近 7 天打卡概览（一行）。
- **指纹去重**：对任务/日程/闪念/习惯四类分别算指纹（如「最近一条的 updatedAt/createdAt + 条数」的轻量字符串），任一变化 → 重新查询该类别；全没变 → 复用缓存文本。时间字段不参与指纹，强制刷新。
- **失败降级**：某类查询失败（DB 异常）→ 该类别跳过不注入，记录日志，不影响对话可用性；快照整体失败 → 回退为仅时间 + 用户画像，不阻断用户消息。
- **查询与组装**：新文件 `ai.context-snapshot.ts`（纯函数组装 + service 调用），单例缓存（进程内 Map<sessionId, {fingerprint, text}>）。
- **决策点见 §8.Q2/Q3**（配额与内容层级）。

## 7. 系统提示词人格化方向（L1 重写）

现版是工具模板文风（「你可以使用以下工具…」），重构方向：

- **人设**：宁序，温柔俏皮的女生生活助理；说话自然、带一点活泼，但**工作在先**——确认操作、明确结果、不啰嗦不卖萌过度（语气权重需用户定，§8.Q4）。
- **结构**：人设 + 当前日期（保留移植）+ 工作方式（直接执行/缺信息先问/失败说明）+ 工具速查（精简版说明，工具 schema 仍由 function-calling 传入）+ 对 L2 快照的引用说明（「上方【】块内的数据是系统刚帮你获取的最新状态，直接使用，不必再查工具」——避免模型拿到快照还重复调 list_* 工具）。
- **输出**：简体中文；任务/日程类操作后简短确认；允许适量 emoji（频度用户定）。

## 10. 已确认结论（本方案基于的事实）

1. SDK **不自动注入**时间/日期/用户数据；现有日期注入在「会话创建时」一次性（跨天缺陷），必须迁到每轮刷新。
2. 每轮刷新的官方机制是 `before_agent_start` 扩展事件（`extensionFactories` 进程内注册），返回 `systemPrompt` 实现替换式更新，不进历史、不重复。
3. custom 消息注入会累积进 jsonl 历史，**不采用**作为快照载体。
4. 快照全部复用现有 service 查询，无新数据通路；快照失败降级不阻断对话。
5. 上下文分四层：系统提示词（开发者维护）/ 用户画像（用户维护）/ 动态快照（自动）/ 对话历史（SDK）；前三层拼接为本轮 systemPrompt，顺序即权重顺序。
