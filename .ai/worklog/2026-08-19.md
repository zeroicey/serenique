## AI 记忆注入与三层上下文设计（需求定稿）

用户需求：给 AI 会话注入「长期记忆（用户维护的静态信息）+ 瞬时记忆（时间 + 内部数据快照）」，优化系统提示词人格化（温柔俏皮女生「宁序」），解决动态上下文每轮更新与不重复。

**调研结论**（pi-coding-agent 0.84.1，bun.lock 锁定，dist 源码实读）：

- SDK **不自动注入**时间/日期/用户数据；现有 `buildSystemPrompt(new Date())` 只在**会话创建时**求值一次 → 跨天继续聊日期是旧的（缺陷）
- 官方「每轮注入」钩子 = `before_agent_start` 扩展事件（`extensionFactories` 进程内注册，可保持 noExtensions 安全隔离），返回 `systemPrompt` 实现**替换式**更新（不进 jsonl 历史，天然不重复）；返回 `message` 会写历史累积，弃用
- 数据源全部复用现有 service 查询（taskGroup/tasks/events/moments/habits）

**已拍板决策**（用户 2026-08-19）：长期记忆走 `ai_memory` 表 + GET/PUT API + Web 编辑框；语气「温柔俏皮但克制」；「AI 绘画」为口误不存在；Q6 记忆自动写入闭环本轮不做（后续增强）；快照配额 ≤1.5~2KB/约 500-700 token。

**四层上下文**（周末讨论后从三层细分为四层，2026-08-19 确认）：L1 静态系统提示词（人格+准则+工具用法，开发者维护定稿后不动）→ L2 用户画像（ai_memory 表，用户自己编辑的唯一入口，紧邻系统提示词权重更高）→ L3 动态快照（时间每轮强制刷新 + 任务/日程/闪记/习惯按指纹缓存去重，失败降级不阻断）→ L4 对话历史；L1+L2+L3 拼接为本轮 systemPrompt（顺序即权重顺序）。
