# 2026-08-20 — Web 端移除顶部导航栏，功能操作下沉到页面内

**背景**：Web 端原布局为「左侧边栏 + 顶部导航栏」。顶部导航栏承载模块标题与功能性操作，
但模块需求差异大（日历/习惯依赖导航切换，闪记等标题显空）、功能锁死在顶栏迫使跨顶栏/页面
用 zustand 共享状态、标题占空间。用户要求移除全局顶部导航栏，保留侧边栏作为模块入口，
功能性操作下沉到页面内部，状态管理相应收敛。

## 改动（commit 298c4bb / 33f9c66）

- **Web 布局**：`app-layout.tsx` 移除 `AppNavbar`，main 区直接渲染（侧边栏保留）；删除
  `app-navbar.tsx/.test`、`module-title-nav.tsx`。
- **路由**：`router.tsx` 移除全部 `handle.nav` / `handle.headerRight` 注册，仅保留懒加载页面。
- **各模块功能下沉**：
  - 闪记：新建按钮 → 列表搜索行右侧；闪记新建页返回 → 页顶 ghost「← 闪记」；空态文案改「点击上方新建」。
  - 日历：新建 → 页顶「新建」按钮（与日期栏同行）；删除 `event-nav.tsx`。
  - 习惯：日期栏 / 总览入口 / 新建 → 今天页顶部操作行；总览页顶「← 今天」+ 新建 + 范围切换；删除 `habit-nav.tsx`。
  - 任务：任务组切换器 → 任务页顶部右对齐；删除 `task-nav.tsx`、`task-store.ts`。
  - 日志：全部置已读 → 筛选行右侧；删除 `audit-nav.tsx`。
  - 宁序：在线状态点 → ChatArea 右上角小圆点；删除 `ai-nav.tsx`。
  - 标签：删除 `tag-nav.tsx`（纯标题）。
- **状态收敛（zustand → 页面 useState + props）**：删除 `stores/habit-ui.ts`、`stores/event-ui.ts`、
  `store/task-store.ts`；habit/event 的 viewedDate/createOpen/editingX 与 task 的 selectedGroupId 均由
  所属页面 useState 持有并通过 props 下发（list→row 一层 drilling 可接受）。保留 `moment-draft`
  （localStorage 草稿）与 `ai-store`（WS 生命周期）。
- **测试**：更新 habit/event 表单与行、任务组切换器测试为 props 注入；audit 页测试补齐
  unread/markRead mock。删除 14 文件、修改 30 文件。

## 部署后修复（commit 33f9c66）：移动端侧边栏入口

- **缺口**（决策审计 blocked 发现）：移动端（<768px）侧边栏是隐藏抽屉，原靠顶栏
  SidebarTrigger 打开；导航栏删除后移动端进入任意模块页**无法切换模块/回首页**，违背用户
  「保留侧边栏作为模块入口」要求。桌面端 SidebarRail（sm+ 可见）仍可折叠，无此问题。
- **修复**：`app-layout.tsx` 用 `useIsMobile` 对移动端在内容区顶部渲染 `SidebarTrigger`（打开
  抽屉），桌面端无顶部条。tsc + 327 tests 全过。

- **审计闭环**：decision-auditor 修复轮复核 D-026 **passed**（移动端缺口机制链逐环有调用点、
  D-026 其余声明与 HEAD 源码一致、机检 tsc/327 tests/lint 全绿）。后台 reviewer 单独触发时遇
  usage 429 / 超时，不影响主审计结论。
